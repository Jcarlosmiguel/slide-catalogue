Applying a slide's annotations in QuPath

Any slide with annotations on its detail page has a Download QuPath script button in the "Slide annotations" section. This generates a Groovy script that recreates that slide's stored annotations - rectangles, ellipses, arrows, measurements, pins, and freehand/polygon shapes - as real QuPath annotation objects on the matching image.

Downloading the script

Next to the download button you can set two options before generating the script:

  • Apply zoom scaling (ticked by default) - some older annotations were recorded at a zoomed-in view rather than full image resolution, and need their coordinates multiplied by a per-annotation zoom factor to land in the right place. If the annotations come in badly offset, wrongly sized, or sitting in blank slide background, untick this box, download again, and try the other mode on a fresh copy of the image.
  • Annotation colour (yellow by default) - pick any colour; it's applied to every annotation the script creates.

Running it in QuPath

  1. Open the exact slide file the script was generated for in QuPath. The script only adds annotations to whatever image is currently open, so the wrong file open means the coordinates land on the wrong tissue entirely.
  2. Open the script editor: Automate → Show script editor.
  3. Load the script: File → Open... inside the script editor and select the downloaded .groovy file, or paste its contents into a new tab.
  4. Run it (the ▶ button, or Ctrl+R / Cmd+R).
  5. Check the result: annotations appear immediately in the viewer and in the Annotations tab, named from their original title (or "Annotation <id>" if untitled), with any recorded description attached.

The script editor's log panel prints a summary line once it finishes, e.g. Added 46 annotation(s) (12 marked invisible in dih (still added), 0 unsupported skipped) from the catalogue. - a quick way to confirm nothing silently failed. Annotations dih itself flagged as "invisible" are still added, just labelled (marked invisible in dih) in their name, since that flag turns out to be genuine per-annotation source data rather than something safe to drop.
